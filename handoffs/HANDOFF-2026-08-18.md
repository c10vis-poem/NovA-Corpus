Root cause of "phone mic doesn't do shit" was **not** hardware, permissions, or VAD:
1. **Missing recorder release.** `termux-microphone-record -q` must run before every capture. Without it, every capture after the first returns silence and Silero correctly reports NO SPEECH. This alone explained the "timing bullshit that never works."
2. **Container lie.** `termux-microphone-record` writes MP4/AAC regardless of filename. A file named `.wav` is `ftypmp42` ISO Media — `sox`, whisper.cpp, Silero all reject it with "RIFF header not found."

Working pattern:
```bash
termux-microphone-record -q >/dev/null 2>&1
termux-microphone-record -f out.m4a -l 8 -r 16000 -c 1 -b 64
ffmpeg -y -i out.m4a -ar 16000 -ac 1 -acodec pcm_s16le out.wav
```
`-r 16000` works fine **after** a release. User cues need `termux-toast` + `termux-vibrate` — stdout is invisible until the command finishes. Do NOT background them with `&`; it holds the pipe open and hangs.

## Voice UX loop — BUILT AND TESTED 2026-08-18

Launch with `ccv` (not `cc` — that would shadow the C compiler). Claude Code runs
inside tmux, which is the only supported way to get text into its prompt.

| Key | Does |
|---|---|
| 🎤 tap (F1) | start talking; tap again to stop, transcribe, and type it into the prompt **without Enter** |
| 🎤 swipe up (F2) | cut the current utterance short |
| 🔊 (F3) | spoken replies on/off |

Files: `~/bin/vv` (mic toggle), `~/bin/speakd` (reply reader), `~/bin/ccv`
(launcher), `~/.tmux.conf` (key bindings), `extra-keys` in `~/.termux/termux.properties`.

**Input** reuses `~/repos/aesop/deploy/phone/stt_process.py` rather than a new
transcriber — it takes the `.m4a` straight from the recorder and runs its own
ffmpeg conversion. Measured 2.7–5.6 s from stop to text in the prompt, including
proot boot and model load. Verified: known-good audio in → correct transcript
typed into the pane, unsubmitted.

**Output** follows the session transcript JSONL, not the terminal. That is what
meets the spec: it cannot lag pages behind (each block is spoken as its line is
appended), scrolling cannot stop it (it never reads the screen), and tool calls
cannot kill it (`tool_use` entries are skipped and the next text block plays).
Verified with a synthetic transcript: `thinking`, `tool_use`, subagent, and user
entries were all correctly ignored; only real assistant text was spoken, including
a block that followed a tool call.

Known limit, by design: Claude Code exposes no per-token hook and writes the
transcript one message block at a time, so speech is **block-granular** — it
follows paragraph-group by paragraph-group, not word by word. The only route to
true token-sync is `tmux pipe-pane` scraping the TUI, which re-reads redrawn
frames and stutters. Rejected.

### speakd bugs found and fixed the same evening

1. `project_dir()` must replace **both** `/` and `.`. Claude Code encodes the cwd
   as `-data-data-com-termux-files-home`; slash-only produced
   `-data-data-com.termux-files-home`, which does not exist, so the follower
   watched nothing forever.
2. It ping-ponged between two concurrently-running sessions' transcripts (three
   switches in 20 s), seeking to end-of-file each time and discarding the blocks
   about to be spoken. Now locks onto one file, reconsiders only after 90 s idle.
3. Only failures were logged, so successful dispatch was invisible — which hid
   both bugs above. Now logs `speaking N chars`.
