## Phase 1: The Architecture Blueprint (What You Are Building)

This is the system design. You need to know this intimately before an
agent writes a single script.

- **The Foundation (No X11):** A 100% headless Termux environment on
  > your Snapdragon 8 Elite. We bypass the buggy graphical layers
  > entirely.

- **The Inference Engine:** GenieX utilizing the QAIRT runtime. This is
  > the muscle that routes local inference directly to your Hexagon NPU
  > for maximum speed without burning CPU cycles.

- **The Memory Architecture (5-Layers):**

  - Raw Storage: Uncompressed PDFs (Cold storage).

  - Master Wiki: Obsidian Markdown files (Human readable context).

  - Almanac: JSONL data (Machine readable structured facts for instant
    > injection).

  - Skill MDs: YAML-headed Markdown files mapping execution actions
    > (e.g., run-qairt.sh).

- **The Voice Layer:** The hybrid STT/TTS pipeline integrated directly
  > into your Open Wiki fork's sockets to control the harness
  > hands-free.

## Phase 2: Knowledge Ingestion (What You Need to Gather)

Before you feed your cloud agents, you have to build their training
curriculum. You need to hunt down and download these specific specs and
dump them into a folder:

1.  **Qualcomm GenieX / QAIRT Documentation:** Specifically the sections
    > on the C SDK, Python bindings, and the Termux/Android
    > implementation rules. They need to know how geniex infer works
    > with the NPU.

2.  **Snapdragon 8 Elite Hexagon NPU Specs:** Documentation on INT8
    > precision and memory allocation limits for the unified memory.

3.  **Termux Environment Rules:** A primer on how Termux handles paths
    > (e.g., /data/data/com.termux/files/usr/) vs standard Linux
    > /usr/bin, and how background processes run.

4.  **Open Wiki API:** Your fork's documentation on how its voice
    > sockets and markdown parsing actually function.

## Phase 3: The Assembly Pipeline (How to Build It)

Once you have the docs, here is how you use them without overwhelming
your models.

1.  **The Formatting Pass:** You will use a heavy cloud model to read
    > those raw PDFs and docs you gathered in Phase 2, and have it
    > rewrite them into your .md and .jsonl formats.

2.  **The Harness Scripts:** You feed the newly formatted Termux Pathing
    > JSONL and GenieX QAIRT MD to your cloud coding agent. You tell it:
    > *"Write the master bash loop that watches for input and triggers
    > the QAIRT inference engine."*

3.  **The Skill Generation:** You have the agent turn every action
    > (e.g., "Summarize this file," "Compile this model") into a
    > SKILL.md file so your on-device agent knows how to trigger it.

## Phase 4: Verification & Execution

This is where the neuro-mesh goes live.

1.  **Drop the Core:** Move the master bash loop and the GenieX binaries
    > onto the tablet.

2.  **Boot the Voice Layer:** Start the STT listener in the background.

3.  **Run the Loop:** The voice layer captures a command, writes it to a
    > buffer, the bash loop sees the buffer, checks the SKILL.md
    > directory, injects facts from the .jsonl Almanac, and passes the
    > context to GenieX for local NPU execution.
